# 08. AI Governance

상태: **확정(Accepted)**. 2026-10-30. D-038~D-040.

## 1. 권한 경계 (D-038)

### 1.1 AI가 할 수 있는 일

| 작업 | 조건 |
|---|---|
| 코드·문서 읽기, 로컬 검사·테스트 실행 | 항상 |
| 작업 브랜치 커밋·푸시 | 항상. 커밋 규칙은 05 §3 |
| PR 생성 | 소유자가 요청했을 때 |
| PR을 통한 `main` 병합 | 아래 1.3을 모두 만족할 때 |
| 설계 문서·decision-log 수정 | 소유자가 결정을 내린 뒤 그 결정만 기록 |

### 1.2 AI가 하지 않는 일

| 금지 | 이유 |
|---|---|
| `main` 직접 푸시, 강제 푸시, 이력 재작성(rebase, amend 후 강제 푸시) | 프로덕션 자동 배포, 기록 손실(D-027) |
| 프로덕션 마이그레이션 적용, DB 덤프·복원 | 운영자 PC에서만(D-034, D-035) |
| Vercel·Supabase·GitHub 설정과 환경변수 변경 | 비가역 또는 즉시 외부 영향(D-032, D-037) |
| 데이터·배포·브랜치 삭제 | 비가역 |
| 검사 우회: `@ts-ignore`, `as any`로 오류 숨기기, 린트 규칙 끄기, 테스트 건너뛰기·삭제, `--no-verify` | D-025, D-027 |
| 비밀값 읽기·출력·커밋 | D-037 |
| 설계 문서에 없는 기능·백엔드 선행 구현 | D-010 이후 범위는 설계 문서가 정함 |
| 사용자가 구현 시작을 명시하기 전 애플리케이션 코드 작성(설계 세션 중) | 설계 세션 규칙 |

금지 작업이 필요하면 AI는 실행하지 않고, 필요한 작업과 이유를 소유자에게 보고한다.

### 1.3 AI 병합 조건 (모두 만족)

1. 소유자가 **해당 세션에서** 병합·배포를 명시적으로 지시
2. PR이 있음(직접 푸시 아님)
3. 필수 검사 `ci` 통과(D-033)
4. 병합 충돌 없음
5. 병합 직전 아래 3줄 보고

```
변경: <무엇이 바뀌는지 한 줄>
비가역 영향: <없음 | 스키마 변경·데이터 형식 변경·외부 설정 필요 등>
CI: <통과 | 실패 단계>
```

비가역 영향이 "없음"이 아니면 소유자의 추가 확인을 받은 뒤 병합한다.

### 1.4 강제 수단

| 수단 | 상태 |
|---|---|
| GitHub `main` 브랜치 보호(PR·`ci` 필수, 직접 푸시 금지) | TBD-014, 소유자 작업. 켜기 전까지 규칙으로만 강제 |
| AI 환경에 프로덕션 비밀값 없음 | D-033, D-037 |

## 2. 규칙 파일 구조 (D-039)

| 파일 | 내용 | 읽는 도구 |
|---|---|---|
| `AGENTS.md`(원본, 150줄 이하) | 명령, 불변 규칙 8개, 권한 경계와 병합 조건, 결정 변경 규칙, 설계 문서 링크 | AGENTS.md를 읽는 도구 전반(도구별 지원은 미확인) |
| `CLAUDE.md` | `@AGENTS.md` 가져오기 + 로컬 서버리스 함수 실행, Vercel 정보, 현재 상태 | Claude Code |

갱신 규칙:
- 규칙에 영향을 주는 결정(decision-log)은 같은 PR에서 `AGENTS.md`를 고친다.
- 근거·세부는 `AGENTS.md`에 복사하지 않고 설계 문서를 링크한다.
- `CLAUDE.md`의 현재 상태(Known state)는 마일스톤이 끝날 때마다 갱신한다.

## 3. 완료 증거 (D-040)

### 3.1 모든 변경

존재하는 검사(현재 `npm run lint`, 도입 후 `typecheck`·Biome·`test`·`test:e2e`·`test:db`·`build`)를 전부 실행해 통과. 실패하면 출력과 함께 보고하고 "완료"라고 하지 않는다.

### 3.2 변경 종류별 추가 증거

| 변경 종류 | 증거 |
|---|---|
| `storage.ts` id 접근 경로 | 다계정 격리 테스트(계정 B가 계정 A의 id로 읽기·수정·삭제 실패) |
| 외부 입력 처리(백업 파일, 공유 링크, 서버 응답) | 손상 입력·상한 초과·허용 목록 밖 필드 테스트 |
| 순수 함수 | 분기 커버리지 100%(D-030) |
| 화면 동작 | 해당 시나리오 E2E 통과 |
| 버그 수정 | 수정 전 실패 → 수정 후 통과하는 테스트 1개 |
| 화면 디자인 | 스크린샷(모바일 폭 기준) PR 첨부 + **소유자 확인 필요** 명시 |
| 문서만 | 링크·결정 ID 일관성 확인 |

테스트 도구 도입 전에는 `docs/design/qa-evidence/` 방식 Playwright 스크립트로 대체한다.

### 3.3 보고 형식 (PR "검증" 절, 채팅 완료 보고)

```
검증됨:
- <검사/테스트 이름>: <결과(통과 n/n)>
미검증:
- <항목>: <이유(실제 기기 필요, 외부 서비스, 소유자 확인 필요 등)>
```

"미검증"이 비어 있지 않으면 "완료"가 아니라 "구현 완료, 미검증 n건"으로 보고한다.
