## 1. 기능 요구사항

### 1.1 플레이 기록 축 🔒

| ID | 요구사항 | 근거 |
|---|---|---|
| FR-PLAY-01 | 기록 입력 시 내 결과는 미선택으로 시작한다. 승자를 지정하면 내 결과가 자동 결정된다(내가 승자면 승리, 다른 사람이 승자면 패배). 결과 없이 저장할 수 없다 | 기존 구현 |
| FR-PLAY-02 | 게임 선택 목록은 검색 전에도 최근 플레이한 게임을 맨 위에 '최근' 표시와 함께 보인다 | 기존 구현 |
| FR-PLAY-03 | 과거 기록의 동행자를 빈도순 칩(최대 8개)으로 보여주고, 탭 한 번으로 추가한다 | 기존 구현 |
| FR-PLAY-04 | 새 기록 저장 후 결과 공유 시트를 띄운다. 공유 문구의 '나'는 공유자 이름으로 바꾼다. 게스트는 공유 전에 표시 이름을 한 번 입력한다 | 기존 구현 |
| FR-PLAY-05 | 공유 문구에 기록을 담은 링크(URL `#play=`)를 넣는다. 사진·평점·후기는 제외한다 | 기존 구현 |
| FR-PLAY-06 | 공유 링크를 열면 결과 카드를 보여주고, 받는 사람이 자기 이름을 고르면 자기 입장의 결과로 바꿔 저장한다. 같은 링크를 두 번 추가하지 않는다 | 기존 구현 |
| FR-PLAY-07 | 플레이 기록 탭: 검색(게임명·사람·장소), 결과 필터 | 기존 구현 |
| FR-PLAY-08 | 수집가 레벨: 기록 5회마다 1레벨 | 기존 구현 |

### 1.3 게임 허브 🆕 (D-002, D-003, D-008)

| ID | 요구사항 |
|---|---|
| FR-HUB-01 | **허브 키 정규화.** NFKC 정규화 → 소문자 → 공백·문장부호·기호 제거. 시드 DB 게임은 한글명·영문명이 같은 허브. 괄호 앞부분과 괄호 안부분은 각각 별칭. 콜론으로 이어진 이름은 별개 게임 |
| FR-HUB-02 | 게임 상세 화면에 해당 허브의 플레이 이력 목록, 총 판수, 내 승률, 함께한 사람(빈도순)을 표시한다. 소장 게임이면 소장 정보도 함께 표시한다 |
| FR-HUB-03 | 게임 탭에 "기록만 있는 게임" 구역을 둔다. 소장하지 않았지만 기록이 있는 허브를 판수와 함께 보여주고, 누르면 허브를 연다 |
| FR-HUB-04 | 백업 복원·공유 링크 수신의 중복 판정과 게임 연결은 FR-HUB-01과 같은 키 함수를 쓴다 |
| FR-HUB-05 | 허브는 저장된 기록에서 계산한다. 저장 구조를 바꾸지 않는다 |

### 1.4 측정 🆕 (D-004, D-005, D-009, D-014, D-015)

| ID | 요구사항 |
|---|---|
| FR-MEAS-01 | GA4는 환경변수 `VITE_GA_MEASUREMENT_ID`가 있을 때만 불러온다. 없으면 아무 데이터도 보내지 않는다 |
| FR-MEAS-02 | 이벤트: `play_saved`, `share_sheet_opened`, `share_link_opened`, `share_link_added`, `game_added`(method: `manual`/`seed`/`scan`), `game_hub_viewed`, `catalog_exported`, `kakao_list_shared`, `backup_exported`, `backup_restored`, `backup_prompt_shown`(group: `ios_safari_browser`/`other`), `backup_login_completed`, `play_photo_added`(count), `backup_upload_result`(result: `ok`/`network`/`auth`/`conflict`/`server`) (D-036), `app_error`(kind: `render`/`storage`/`cloud`/`scan`/`unknown`) (D-036) |
| FR-MEAS-03 | 이벤트 매개변수는 FR-MEAS-02에 적힌 값 목록만 허용한다. 이름·게임명·장소·점수·사진은 보내지 않는다. 허용 목록 밖의 값은 코드에서 전송 전에 막는다 |
| FR-MEAS-04 | Vercel Web Analytics로 방문 추세를 수집한다(`@vercel/analytics/react`) |

### 1.5 클라우드 백업 🆕 (D-010~D-016)

| ID | 요구사항 |
|---|---|
| FR-CLOUD-01 | 로그인: 카카오 로그인, 이메일 매직링크. 비밀번호는 서버에 저장하지 않는다 |
| FR-CLOUD-02 | 기본 저장소는 기기다. 로그인한 사용자의 게임·기록·이름·점수를 서버에 자동 백업한다. 저장 후 몇 초간 추가 변경을 묶어 한 번에 전송한다(묶음 간격은 PHASE 4). 사진 축소본은 새로 생긴 것만 보낸다 (D-017) |
| FR-CLOUD-03 | 사진은 긴 변 400px 축소본만 서버에 올린다. 원본은 기기에만 둔다 |
| FR-CLOUD-04 | 다른 기기에서 로그인하면 서버 백업을 기기 데이터에 합친다. 합치기는 기존 복원 규칙(새 id, 필드 화이트리스트, 중복 제외)을 따른다 |
| FR-CLOUD-05 | 로그인 권유: 아이폰 사파리에서 설치하지 않고 쓰는 게스트는 첫 기록 후, 그 외 게스트는 기록 3회째. 공유 시트가 닫힌 뒤 표시. 닫으면 기록 5회마다 재권유, 최대 3회 |
| FR-CLOUD-06 | 신규 로컬 회원가입을 중단한다. 기존 로컬 계정은 로그인할 수 있고, "클라우드로 옮기기"로 데이터를 클라우드 계정에 올릴 수 있다 |
| FR-CLOUD-07 | 계정 삭제 시 서버의 기록·게임·사진 축소본을 즉시 영구 삭제한다. 기기 데이터는 지우지 않으며 이 사실을 삭제 확인 화면에 표시한다 |
| FR-CLOUD-08 | 백업 화면에 "사진은 작은 크기로만 백업돼요"와 마지막 백업 시각을 표시한다 |
| FR-CLOUD-09 | 서버나 네트워크가 실패해도 기록 입력·조회는 기기에서 정상 동작한다. 실패한 백업은 "대기 중"으로 두고, 앱을 열 때와 연결이 복구될 때 다시 시도한다 (D-017) |
| FR-CLOUD-10 | 백업 상태를 완료·대기 중·실패 3종으로 관리하고 백업 화면에 표시한다 (D-017) |
| FR-CLOUD-11 | 백업이 연속 3회 실패하면 "백업이 안 되고 있어요. 파일로 내보내 두세요" 안내와 내보내기 버튼을 표시한다. 성공 시 카운트 초기화. 닫으면 다음 연속 3회 실패 때 다시 표시 (D-036) |

## 2. 비기능 요구사항

| ID | 범주 | 요구사항 | 상태 |
|---|---|---|---|
| NFR-01 | 데이터 격리 | 다른 계정의 레코드를 읽기·수정·삭제할 수 없다. id로 접근하는 모든 경로는 소유자를 확인한다. 검증은 다계정 테스트로 한다 | 확정(기존 원칙) |
| NFR-02 | 외부 입력 | 공유 링크, 백업 파일, 서버 응답은 신뢰하지 않는 입력으로 다룬다. 필드 화이트리스트, 크기·개수 제한, 새 id 발급 | 확정(기존 원칙) |
| NFR-03 | 비밀값 | API 키(Gemini 등)와 서버 비밀값은 클라이언트 번들에 넣지 않는다 | 확정(기존 원칙) |
| NFR-04 | 가용성 | 서버 장애가 기록 입력을 막지 않는다(FR-CLOUD-09) | 확정(D-011) |
| NFR-05 | 성능 | 첫 화면 JS 번들(gzip)을 현재 대비 +15% 이내로 유지. 기준값: 376.6KB(2026-10-30 실측) | 확정(D-018) |
| NFR-06 | 호환성 | 최신 iOS 사파리, 안드로이드 크롬, 데스크톱 크롬에서 동작 | 확정(D-018) |
| NFR-07 | 기록 속도 | 같은 멤버로 두 번째 기록할 때 30초 이내(사용자 테스트로 측정) | 확정(D-018, 가정 목표) |
| NFR-08 | 개인정보 | 분석 이벤트에 개인 정보 없음(FR-MEAS-03). 서버에는 로그인하고 동의한 사용자의 데이터만 저장 | 확정 |

## 3. 사용자 시나리오

| ID | 시나리오 |
|---|---|
| S-01 | 모임 기록 담당자가 게임 직후 기록하고(FR-PLAY-01~03), 공유 시트로 단톡방에 링크를 보낸다(FR-PLAY-04~05) |
| S-02 | 친구가 링크를 열어 자기 이름을 고르고 자기 기록에 추가한다(FR-PLAY-06). 그 게임을 소장하고 있으면 허브에 모인다(FR-HUB-04) |
| S-03 | 컬렉터가 박스 사진으로 게임을 일괄 등록하고(FR-COL-01), 기록이 쌓인 뒤 게임 상세에서 판수와 승률을 본다(FR-HUB-02) |
| S-04 | 아이폰 사파리 게스트가 첫 기록 후 로그인 권유를 받고(FR-CLOUD-05), 카카오로 로그인해 백업을 켠다(FR-CLOUD-01~02) |
| S-05 | 폰을 바꾼 사용자가 새 기기에서 로그인해 기록을 되찾는다(FR-CLOUD-04) |
| S-06 | 사용자가 계정을 삭제하면 서버 데이터가 지워지고 기기 데이터는 남는다(FR-CLOUD-07) |

## 4. 완료 기준 (Acceptance Criteria, 신규 기능)

| 대상 | Given | When | Then |
|---|---|---|---|
| FR-HUB-01 | 시드의 변형판 5쌍(스플렌더/스플렌더 듀얼 등) | 키를 계산하면 | 각 쌍은 서로 다른 키 |
| FR-HUB-01 | "세븐원더스", "세븐 원더스", "7 Wonders" | 키를 계산하면 | 모두 같은 허브 |
| FR-HUB-01 | "Diamant", "Incan Gold", "디아망" | 키를 계산하면 | 모두 같은 허브 |
| FR-HUB-02 | 같은 허브 기록 4판(2승) | 게임 상세를 열면 | 4판, 승률 50%, 이력 4건 |
| FR-HUB-03 | 소장하지 않은 "카탄" 기록 2판 | 게임 탭을 열면 | "기록만 있는 게임"에 카탄 2판 |
| FR-MEAS-01 | 측정 ID 미설정 | 기록을 저장하면 | 외부로 나가는 분석 요청 0건 |
| FR-MEAS-03 | 측정 ID 설정 | 기록을 저장하면 | `play_saved` 요청에 이름·게임명·장소 문자열이 없음 |
| FR-CLOUD-04 | 서버에 기록 10건, 새 기기에 기록 2건(그중 1건 중복) | 로그인하면 | 기기 기록 11건, 모든 id가 새로 발급됨 |
| FR-CLOUD-07 | 서버에 기록이 있는 계정 | 계정을 삭제하면 | 서버 조회 결과 0건, 기기 기록은 그대로 |
| FR-CLOUD-09 | 네트워크 끊김 | 기록을 저장하면 | 저장 성공, 백업은 대기 상태로 표시되고 연결 후 재시도 |
| FR-CLOUD-11 | 서버가 계속 500 응답 | 백업 시도가 3회 연속 실패하면 | 내보내기 권유 표시, `backup_upload_result`(result=`server`) 3건 |
| NFR-01 | 계정 A, B의 서버 데이터 | B로 로그인해 A의 레코드 id로 요청하면 | 거부 |
